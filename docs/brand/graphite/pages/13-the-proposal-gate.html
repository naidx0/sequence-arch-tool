Sheet 13 · The proposal gate

Drawing a thing that is not true yet

Every other sheet in this book rests on one promise: what is drawn was traced to evidence in the repository. This sheet is the exception that keeps that promise honest. When the assistant proposes a change to the topology — a service that does not exist, an edge nobody has written — the board has to show it before it is true, and the reader has to be unable to mistake it for something that is.

So the register is not a colour. A proposed node is drawn in the ghost silhouette: the real card's geometry, dashed at --w-rule, filled with nothing, its name in --ink-3. It reads as an outline of a decision, which is what it is. Sheet 12's gate ends a run; this gate ends a proposal, and the difference is that the subject is on the canvas rather than in the transcript.

A ghost is never counted. No coverage chip, no node count, no "8 services" total includes a proposal. The moment a number would have to explain itself, the number is wrong.

13.1

The ghost silhouette

same box · dashed --w-rule · no fill

The ghost borrows the real card's width, padding and type ramp exactly, and changes three things: the border becomes dashed, the fill goes to nothing, and the name drops one ink step. Borrowing the geometry is deliberate — a proposal that is a different size from the thing it proposes cannot be read as a preview of it, and the reader ends up comparing shapes instead of reading a decision. Sheet 03's rule still holds underneath: the kind is still carried by silhouette, not by hue, so a proposed store and a proposed service remain distinguishable from each other while both remain distinguishable from anything real.

13.2

A proposed edge, and why it is not the declared dash

--flow-dash-declared is taken

Sheet 04 already spends a dash: --flow-dash-declared marks an edge asserted in config that no call site confirms. That dash says claimed but unproved, which is a statement about the repository. A proposal says not yet real, which is a statement about a decision the reader has not made. Reusing one dash for both would make the board answer "is this in my code?" and "am I about to add this?" with the same mark. The proposed edge is the declared dash plus the ghost's ink drop, and it carries no arrowhead until it is accepted — direction is a property of a real call.

proposed not real yet — no arrowhead until accepted
13.3

The gate sits with the ghost, not with the chat

--sp-12 below the lowest ghost

Sheet 12's run gate lives at the end of the transcript, because a run is a thing the assistant did. A topology proposal is a thing about to happen to the canvas, so its gate belongs to the canvas: anchored under the proposal's bounding box, offset --sp-12, moving with the board when it pans. A gate in the left column asking about objects on the right makes the reader hold two places at once to answer one question.

Deny is not destructive and is not styled as though it were. Denying removes the ghosts and changes nothing else — no file is written, nothing real is touched, so there is no red, no confirm-again, and no warning register. Accept carries --accent-solid because it is the one action on the surface that changes state. One primary, per sheet 10's control ladder.

13.4

What must never happen

the failure modes this sheet exists to forbid
Never — a ghost in a count

The coverage chip, the node count and the legend read the traced graph only. A total that silently includes proposals makes every number on the board a question.

Never — accent on the ghost

Accent means active. Painting the proposal with it makes the not-yet-real the loudest object on the canvas.

Never — a red deny

Denying writes nothing. A destructive register for a non-destructive action teaches the reader to distrust the register.

Never — ghosts that outlive the gate

Close the gate and the ghosts go with it. A proposal with no gate is an edge on the board that nothing accounts for.

Never — the declared dash reused

--flow-dash-declared answers "is this in my code?". Reusing it to answer "am I adding this?" collapses two different questions into one mark.

Never — a moving board

No auto-pan, no auto-zoom to the proposal. Sheet 05's rule holds: the camera is the reader's.
