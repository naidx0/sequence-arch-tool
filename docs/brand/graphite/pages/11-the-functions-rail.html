Sheet 11 · The functions rail

The functions rail

The right-hand rail is Sequence's index: files and, inside them, functions. It is functions-first because a function is the smallest thing on the board that can be played — click one and the canvas re-sorts and runs its service-to-service flow. Everything else in the rail exists to get you to that row.

Nothing on this sheet is new. The rail is Graphite's own thread rail with its meanings changed: a section head becomes a board card, a folder row becomes a file, a thread row becomes a function. Same three rungs, same indent, same states, same ladder held on sheet 10.

11.1

The rail, whole

--rail-w · --surface-1 · one border, on the left

This column has a name: the index rail. It is the shell's third column, it holds one thing — the index of the open repository, board card above file above function — and it is the only surface on the right-hand side of the window. One rail, one scroller, one row pitch per rung. It uses the .pane chassis — a --surface-1 column with a single --edge hairline on its left, a .pane-hd at --topbar-h so its header lands on the same 44px line as the chat header and the app bar, and a .pane-scroll that is the only thing in the column that scrolls.

The header carries the word, not a glyph. ic-panel is the app bar's control for showing and hiding this rail, and sheet 09 holds it to that one host. A mark that both opens a surface and labels it is one glyph doing two jobs, which is the defect 11.3 forbids for the row kinds; the rail's own header is titled in words, and the only glyphs in it are the actions on the right.

The width is the user's. It is dragged within the clamps and remembered, because re-sizing a panel on every launch is the definition of not customisable. The clamps are the design; the value inside them is not.

This departs from the substrate. The substrate lays its shell out as .win — three columns, var(--rail-w) minmax(0,1fr) var(--pane-w) — and sizes the third at --pane-w (392px), the width Graphite gives its file detail column. Sequence's third column is this rail: an index that drives the canvas, not a properties column beside one, and the whole right-hand side of the window is it. So the rail is drawn at --rail-w (280px) inside --rail-w-min 216 and --rail-w-max 400, and --pane-w keeps exactly one host and it is the substrate's: .win's third grid column, inherited from Graphite and left alone so a shell specimen in this book and a shell specimen in Graphite stay the same object. No Sequence surface asks for it — not this rail, not a menu, not a specimen width — and the gap between the chassis and the rail is the handback: the shell should size its third column at --rail-w, and until it does, every shell drawn in this book is 112px wider on the right than the product it describes. --pane-w-min is not borrowed here either. It is a resize clamp; the 320px a menu or a path field wants is --menu-w, which the substrate declares for that job so sheet 01's prohibition can be obeyed rather than argued with.
11.2

Three rungs, and no fourth

24 · 30 · 28 · indent --sp-16

Row height is semantic, not decorative. A board card is a label, so it is the 24px eyebrow rung. A file is structure that opens and closes, so it is the 30px rung. A function is the object you act on, so it is the 28px rung — the same rung a thread gets in the chat rail, because clicking it does the same size of thing.

The function row is deliberately not the smallest rung on the sheet. 26px is the footnote height — a tool call, a key/value line. In a functions-first rail the function is the point of the rail, and demoting it to a footnote would say the opposite of what the product means. Density is solved by the filter and by the card grouping, never by a shorter row.

Where the Files projection nests deeper, the step stays --sp-16 and the name gives way, not the indent: a path truncates at the front, because the identity of …/board/boardFocusModel.ts is its tail, and a function name truncates at the end, because the identity of a name is its head.

11.3

A file row is not a function row

four channels, none of them hue

The rail obeys the same law as the board: a kind is a category and a category never earns a hue. A file and a function are told apart by height, by indent, by icon and by type family — four channels, all of which survive a greyscale render and a colour-blind reader.

Mono sets one step below the sans beside it, everywhere. A file path is a name a human wrote and reads as prose; a function name is an identifier and reads as a value. The rail already draws ic-fn on every function row; the count now says the same word with the same mark.

The card head's icon is not decoration. It is the same glyph the node carries on the board, from the same one-icon-per-kind vocabulary — so the rail and the canvas name a service the same way, and a reader who learns the mark once has learned it in both places. This is the rail's half of the architecture's no-hue differentiation: the board proves the icons at a distance, the rail proves them at 12px.

11.4

Rest, hover, selected, playing, focus

one accent mark, for one fact

Four hundred rows can be at rest, one can be hovered, one can be selected and exactly one can be playing. Selection and playing are different claims and they are drawn differently: selection is where the keyboard is, and is neutral; playing is what the canvas is currently showing, and is the one place in this rail the accent appears.

Hover may never out-weigh playing. The playing mark is the one thing a reader hunts for in this rail, and a hover that paints heavier than it turns the pointer into a liar.

The substrate needs one addition. .thread.sel paints --state-selected and nothing else. The playing state adds an inset --w-rule bar in --accent, drawn here inline. It should become part of the class, so that "playing" is one decision made once rather than a shadow retyped at every call site. Raised as a handback, not invented locally.
11.5

The search field

.inputwrap · .input.sm · 24px · --r-8

One field, always visible, directly under the header and above the scroller so it never scrolls away. It is .input.sm — 24px, the compact control rung — inside .inputwrap, which reserves the same 14px icon slot the rows use, so the search glyph sits on the rail's one vertical alignment.

Typing switches the rail into filter mode. A row matches on its name or its repo-relative path; every match is shown with its ancestors revealed, so a hit is never hidden behind a collapsed parent; and order still follows the repo, so the result reads as the project rather than as a search dump.

11.6

What a click does

the rail drives the canvas

Clicking a function row is the rail's whole purpose. The canvas re-sorts around that function's own service and then plays the flow: each hop lights in turn, the edges on the path take --flow-onflow at --w-flow, and everything not on the path drops to --board-dim-opacity rather than disappearing — a node you cannot see is a node you cannot rule out.

The accent on the row and the accent on the played edge are the same claim in two places: this is the thing you asked for. That is why the trace card below the row is never accent-tinted — two accent marks for one fact read as two facts.

11.7

Empty, scanning, stale

--edge-strong dashed · --st-active · --st-stalled

Three ways for the rail to have nothing to show, and they are not the same thing. Nothing read yet is an invitation. Nothing matched is a filter you can clear. Nothing found here is a fact about the repository. Each gets its own sentence, because "No results" for all three is the rail refusing to answer.

While a scan is running the rail does not draw a skeleton. A grey bar where a row will be is a shape the engine has not measured, and this book does not draw numbers or rows it does not have. Real rows arrive as they are found, the header carries a pulsing --st-active dot and the word, and the running count is a marked placeholder until the scan ends.

11.8

The rail's four rules

1. Three rungs, and no fourth. 24px card head, --row-h file, --row-h-thread function. A new kind of row is a new rung, and a new rung needs an owner's name on it.

2. No hue for a category. Height, indent, icon and type family tell the rows apart. The only colours this rail may draw are the accent on the playing row and a verdict word on a claim the scan could not confirm.

3. One accent mark for one fact. The playing row and the played edge are the same claim. Nothing between them — the trace card, the chips, the arrows — is tinted.

4. Every number is derivable or marked. A count may be a literal only when the rows it counts are on screen. A line number, a repository name, an elapsed time and a running total are placeholders, in the rail exactly as everywhere else.
