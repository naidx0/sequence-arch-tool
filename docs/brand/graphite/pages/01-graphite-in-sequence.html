Sheet 01 · Part one, Foundations · The cover

Graphite in Sequence

Every hue on screen is a claim about the world, and there are never more hues than there are claims. That is the whole design in one sentence, and it is the first thing on this sheet because everything after it is a consequence. A red Won't fit is alarming here because it is the only red on the screen. An amber Defaulted tag is noticeable because nothing else is amber. The moment a divider, a heading, a border or a node kind takes a colour, the claim system loses the contrast it lives on — and the chrome wins, because there is more of it.

Graphite is not Sequence's design language. It is ml-harness's design language, inherited here wholesale by owner decision: a neutral near-black ground with almost no chroma, six greys, one low-chroma gold accent, no gradients anywhere in the chrome, Apple-grade rounding applied consistently, and compact as the only density. Sequence adds one thing Graphite never needed — a live architecture canvas — and adds it inside the laws rather than beside them.

You extend Graphite. You do not redesign it. If you find yourself inventing a colour, a radius, a type size or a spacing value, stop: the answer is already in _core.html. If the shape you need genuinely is not there, use the nearest thing that is and say so in your handback, where somebody can decide once for everybody. Six local inventions are six contradictions.

01.1

Where this comes from, and what outranks what

so a disagreement has an answer instead of an argument

Three brand directions were built for ml-harness and compared; Direction A — Graphite — was chosen. The owner then directed that Sequence adopt that same book rather than keep a parallel language of its own. This sheet extends that decision to a full reference for a different product. It does not reopen it. Nothing on any Sequence sheet may contradict a Graphite page, and where Sequence's own shipped code contradicts one, the code is what gets corrected.

01.2

Law one, which the other four exist to protect

hue is a budget, and it is already fully committed

Green means it fits, or it passed, or it was measured. Amber means it spills, or it stalled, or the number was defaulted. Red means it will not run, or it failed, or it is blocked. Blue means running, or inferred — a notice, not a verdict. Grey means we do not know and we are refusing to guess. gold means the product is speaking. Nothing is left over for decoration, and that is the point rather than the constraint: a new colour cannot be added casually, because there is nowhere for it to hide.

The consequence is written as a prohibition, because prohibitions survive handover better than intentions. Dividers, headings, section rules, borders, icons at rest, node borders, node fills and every other piece of chrome are never coloured. A coloured border and a coloured verdict are the same signal to somebody scanning at speed, and the border wins by volume — it is on every node on the board, while the verdict is on one.

01.3

The other four

each one is testable, and each one has already caught a defect here

These are not preferences. Every one of them is written as something a reviewer can check against a rendered page and be right or wrong about, because the review loop for this design is the same as the review loop for the code: look at it, screenshot it, measure it, and give the job of disbelieving it to somebody who did not draw it.

Law two — gold is the accent, and it can never be mistaken for a verdict

It was chosen by elimination rather than by taste.

Green is --fits. Amber is --spills. Red is --wont. Blue is --info and every active run state. Grey is --unknown. gold is the only region of the wheel left, and taking it means the accent can never be read as good, bad, warning or information. It means exactly one thing: the product is speaking, or the product needs you — send, selection, focus.

28px, --r-full, --accent-solid. The signature element, and the only object on a screen wearing the accent at full saturation. It is never square.

Law three — compact is the only density

Airy is a defect, not a preference.

The working type sizes are 10, 11 and 12px and the rhythm they sit in is fixed. A comfortable mode may exist for testing; nothing is designed for it and nothing is judged in it. On the canvas the answer to crowding is level of detail — drop the subtitle, then the tag, then the title — never a smaller type size. Text below the floor is not compact, it is unreadable.

Law four — never invent a number

The rule this book exists to enforce, and the one a graph product breaks first.

Any value the engine computes at run time is a marked placeholder. It is set in --ink-2 under a dotted underline so it can never be mistaken for a measurement, screenshotted as evidence, or pasted into marketing. Use ‹ ›, never the less-than and greater-than signs.

Read ‹file count› files and traced ‹edge count› calls in ‹elapsed›.

The graph-shaped version of this law: never draw an edge the analyzer did not find. A fabricated chain of parts is an invented number with a stroke on it.

Law five — both themes ship at equal quality

Deferred for Sequence, not waived. See owner decision 1 below.

In dark, elevation reads as lightness — each surface a few percent lighter than the one below, plus a 1px inset top highlight. In light, three of the four raised surfaces are the same white and elevation reads as shadow and a hairline ring instead. Interaction overlays move downward in light and upward in dark, because a hovered light row that gets lighter is the classic light-mode failure.

Practically, and this part is not deferred: never hard-code a hex, anywhere, for any reason. Write the token. Both themes then follow for free, which is exactly what makes finishing light later a fill-in job rather than a rebuild.

01.4

Owner decision 1 — light is deferred

Max, 2026-08-19 · outranks law five
Verbatim. “ignore light theme for the moment… Don't tune the light theme now.”

Law five requires both themes at equal quality. That requirement is deferred, not waived. The distinction is the whole decision: no agent spends effort tuning light surfaces, choosing light values, or building light specimens — and no agent is permitted to write a colour in a shape that would make finishing light later a re-architecture. Every token is still declared in Graphite's three-state form, with the complete light palette present on bare :root even though nobody is judging it yet. 

:root                              /* the complete light palette */

@media (prefers-color-scheme: dark)
  :root:not([data-theme="light"])  /* system default resolves dark */

:root[data-theme="dark"]           /* an explicit choice wins */

There are three viewer states, not two

Light, dark, and no choice at all — which follows the system and is what an untouched page shows.

All three resolve because the palette is declared for all three. Judging a sheet in dark only is correct under this decision; declaring a token in dark only is not, and is the one way a deferral turns into a rebuild.

Practical test for a reviewer: strip every [data-theme] and media block from the token layer and count the colours left on :root. If any is missing, this decision has been broken rather than followed.

01.5

Owner decision 2 — node kinds differentiate without hue

the single most important rule in this book

This is the one real collision between Graphite and Sequence. Graphite has no architecture canvas; Sequence's whole product is one. Sequence had been colouring node borders and fills by kind, which law one forbids outright — coloured chrome, and more hues than claims — and which had the further consequence that the layout engine sorted the coloured kinds toward one side, so half of every board read as a wall of “passed” and “warning” before a single claim had been made.

Verbatim. “We kind of need some type of contrast differentiation. If you can solve that while staying true to Graphite, that'd be cool… some subtle grain, some subtle graphiting… dotted lines, stuff like that… Maybe use shapes and icons in higher quantities to really differentiate the actual features… We just want a good visual experience, but not overpower the eyes too much. Don't kill people when they look at it.”

Resolution: kind is carried by four non-chromatic channels and one glyph, never by hue. A node's kind is a category; a node's state is a claim. Only the second one earns colour.

The kind label is mono at --t-10 in --ink-3 — a category set as a category. It is never a .verdict badge: green means passed, and a service has not passed anything.

The word for that kind is Datastore, and it is the code that gets corrected. Shipped code disagrees with itself before it disagrees with the book. packages/schema/src/seqdiagram.ts declares the node kind 'datastore' in SeqDiagramNodeKind; packages/web/src/product/arch/archKinds.ts maps that kind to a presentation kind 'storage', whose ARCH_KIND_LEGEND entry carries the label Storage. Two words for one kind, and the second one exists only in the legend. The book uses Datastore, everywhere, on every sheet — specimen labels, kind labels and prose — because that is the word the grounded schema already uses, and a reference that renamed it would put the book at odds with the data model instead of with one string. The label in ARCH_KIND_LEGEND is the defect, and §01.1 already says which way that resolves: where shipped code contradicts a page here, the code is what gets corrected. The CSS class stays .n-store and the tokens stay --arch-*-store; those are short forms of the same word, not a third one, and renaming them buys nothing. No sheet may print Storage for a node kind.

The binding invariant

Stated so a test can enforce it, because it survives refactors that swap one token for another.

Every architecture node kind must remain distinguishable with all colour removed, at every size the silhouette is drawn, from the radii that actually paint. Render the board in greyscale at the size it ships: if two kinds go ambiguous, the differentiation was leaning on hue — or on a value that was declared and never painted.

The middle clause is the one that was missing, and its absence is why this book was audited. CSS scales every corner on a side by f = min(side length ÷ sum of the radii on that side), so any radius at or above half the height paints as a stadium. On a 26×18 chip --r-14, --r-18 and --r-full all render at 9px — three kinds, one shape — while the token file still says they differ. Proving this invariant against declared token values proves nothing about the picture. It is proved against pixels.

A second, narrower invariant: no kind token may introduce a hue that is not already in the Graphite palette, and none may collide with a verdict hue. The strongest form of both, and the one actually implemented, is that there is no colour token in the kind namespace at all — nothing to collide with, and nothing to drift.

The same six with the labels taken away

Silhouette, border treatment and tone only. No icon, no text, no hue.

Six swatches, six kinds. Border weight is the weakest channel in the set and never carries a pair on its own: a 1.5px border snaps to 1px on a 1x display, so it reinforces and nothing more. Each swatch is drawn at half a card — --arch-card-w and --arch-card-min-h both halved, so the aspect is a card’s — because that is the honest floor of this ladder. At this size the folder tab already paints 6px, the chamfer 8px and the cylinder arcs 7px — the features are at their limit here, not one step above it. Below it they go under, silhouette stops separating the six, and the icon becomes the carrier. Do not claim the outlines still separate below this size; state that the glyph has taken over.

01.6

What Sequence adds, that Graphite has no equivalent for

six gaps · each is a gap, not a licence

Sequence is a local-first, visual-first code editor: it reads a repository into a live architecture graph you can read, edit, draw and reason about, with a grounded assistant and runnable agent workflows — one live canvas, chat on the left, a file and functions rail on the right. Graphite was written for a chat product with cards in it. It draws no plane, no object in a plane, no connector, and no containment. Those six gaps below are the entire reason this book exists, and each one is paid for with geometry, an alias, or a glyph — never with a new colour.

01.7

The surface ladder, and the accent, once

every value is a decision about height, not about colour

Six planes and three border weights. Nothing on this ladder carries a hue, and that is the first fact about it — a product whose most valuable sentence is this is what your repository actually does cannot afford to spend colour on the furniture that sentence has to stand out from. A node card gets separated from the board by tone and elevation; the border can then stay quiet at --edge, which is exactly what frees the hue budget for claims.

If a screen shows gold twice for two different reasons, one of them is wrong. The thread row is drawn at --rail-w, because in Sequence a thread row lives in the chat rail on the left — Graphite put its threads in the right-hand pane and sized them at --pane-w; Sequence's right-hand column is the index rail, which sheet 11 settles. The rename field is drawn at --pane-w-min on purpose, and it is the one specimen in the book allowed to be: it exists to show that the field stays usable at the narrowest drag, so the clamp is its subject. Everywhere else, --pane-w-min is a resize clamp and nothing else — it is never borrowed as a convenient specimen width, for the same reason one glyph never carries two meanings. A menu or a field that wants 320px asks for --menu-w, which the substrate declares for that job.

01.8

Before you write a sheet

eleven ways to be wrong, and what to do instead

This sheet is the first one an author reads, so it carries the checks that would otherwise only be discovered in review. Every row below is a real decision somebody has to make, and the right answer to every one of them is already settled — in the substrate, on this sheet, or on sheet 10. None of them is yours to decide again.

If you are about to…Stop. Instead:
write a hexWrite the token. There is no permitted raw hex on any sheet — not in a specimen, not in an inline style, not “just for this one swatch”.
give a node kind a colourDecision 2. Icon, silhouette, border treatment, tone. Check it in greyscale before you claim it works.
colour a border, divider or headingLaw one. --edge, --edge-strong, --edge-faint. That is the whole vocabulary.
use red for something unconfirmed--unknown. Red is failed or blocked. A claim nobody could check has not failed at anything.
write a plausible numberA marked placeholder: ‹detected value›. A literal is permitted only when a reader can derive it from what is drawn on the sheet.
add a radius or a type sizeSix radii plus --r-bar, and nine type steps. --r-6, --r-12, --r-16 and --r-20 do not exist and resolve to a square corner.
add a CSS classUse the nearest one that exists and name the gap in your handback. A sheet carries no <style> block. Inline style="" is for layout only, in tokens.
tune a light valueDecision 1. Declare it in the three-state shape and move on. Nobody is judging light yet, and nobody may make finishing it a rebuild.
number a section 3.2Zero-pad it: 03.2. An eyebrow is the sheet’s own data-page-num followed by the section index, and data-page-num is zero-padded — so sheet 3’s second section is 03.2, never 3.2. Prose cross-references use the same form. This is the convention for the whole book; a sheet that disagrees is the one that is wrong.
set a line-height in pixelsWrite the ramp token that pairs with the size: --t-12 takes --lh-12, --t-13 takes --lh-13. The line ramp is as closed as the size ramp — sheet 10 settles it — so a bare 17px or 19px is an off-ladder value wearing a different name.
write “Storage” for a data nodeThe book’s word is Datastore. See §01.5 — the shipped legend label is the thing that gets corrected, not the book, and both words may not stay in play.

One last thing, addressed to whoever writes the next sheet. Show the thing, then state the rule beneath it — a reference that describes a specimen instead of rendering one is a document nobody can disagree with, which is the same as a document nobody can check. Set every value as a token reference so the reader can find it. And judge the result by looking at it: a change is not done because it renders, it is done when somebody has looked at the picture and compared it to what the laws say it should be.
