Sheet 08 · The board

Density, overflow and the honest “+N more”

A real repository does not fit in the frame. That is the normal case on the one surface whose whole job is to be the repository, not the exception — so the board’s behaviour when it runs out of room is a design, not a fallback.

A list’s overflow is a scrollbar. A graph’s overflow is a hairball. So the board makes room by dropping detail, never by dropping nodes: the only place a count is capped is inside a list, and there the cap is a control you can press. A node the analyzer found and the board silently declined to draw is a lie of omission.

08.1

The budget is the frame, not a node count

--arch-card-w · --arch-card-min-h · --board-field-pitch

There is no maximum number of nodes. What is budgeted is detail: the frame holds ‹frame area› divided by the footprint of the current rung, and when that runs out the cards drop a rung — they do not disappear and their type does not shrink. The count of drawn nodes is therefore never a decision the board makes; it is a fact about the graph, and the census below states it rather than trimming it.

08.2

Level of detail: rungs drop whole, type never shrinks

expand row → subtitle → port → title → silhouette → icon

Detail leaves in a fixed order, and each rung leaves whole — the card never keeps a half of anything. The order is by how much of the answer the reader loses: the expand row is an invitation, the subtitle is a sentence, the port is a fact, the title is the name, and the kind goes last, because it is the only thing still readable at the zoom where everything else has gone. But the kind does not ride one carrier all the way down. It is handed over: the silhouette carries it to half a card and no further, the icon carries it below that, and below the icon nothing does. A ladder that ended at “silhouette” would be claiming a separation the renderer stops giving.

Rung 1 is the only rung that reserves --arch-card-min-h; every rung below it is content‑tall, because a card that has dropped its subtitle and still holds the room for it is a block box with one line at the top and dead ground under it. Each rung is a strict subset of the one before it — nothing is added back. Rungs 1 to 5 are one chassis: same silhouette, same border treatment, same icon, only fewer lines. Rungs 6 and 7 are where a carrier itself is given up, and the sheet has to say which one rather than draw one and imply the other survived.

Drop the rung and keep its room. The floor was written for a card with a subtitle, so a card without one becomes a block box holding one line over dead ground — and the emptiest kinds, which are the ones that never had a subtitle, get the most of it.

Two rules follow. A rung is dropped by the level of detail, never by the reader, and the ladder is the same on every kind — two kinds that lost rungs in a different order would be two chassis. A dropped rung takes its room with it: the height floor governs the resting card, not a card that has already given something up. Type is never the thing that gives; --t-10 is the floor at every zoom, because below it a label is not small text, it is no text.

08.3

The honest “+N more”

a control, not a caption

Overflow only ever happens in a list — the interior rail, the flow picker, a module’s member strip — because a list is the only place on this product where trimming is cheaper than drawing. Wherever it happens, the disclosure says four things and no fewer.

What “+N more” means

Four clauses. Drop one and the count stops being evidence.

N is a real count of real things, computed — so it is a placeholder, never a figure
The N are the same kind of thing as the rows above — never a mixed remainder
It is reachable: pressing it shows them, and there is no second cap behind it

08.4

A container states what it is holding

census by icon and count — never by hue, never by bar

Containment is the board’s main answer to density: a module folds its members away and takes their room. That is only allowed because the fold is declared. A module carries its full member count in its header whether it is open or shut, and it summarises what it holds as a kind census — one icon per kind and a number. A bar or a tint would spend hue on a category, which is the defect this whole rebuild exists to remove.

Edges that crossed the wall survive the fold, re-anchored to the module card, because an edge into a member is still an edge into the module — folding a container may never delete evidence.

08.5

Empty is three parts, and “you emptied it” is a different sentence

.empty · dashed --edge-strong · --r-14

Every empty state carries the same three parts: what is not here, why it is not here, and one thing to do about it. The second part is the one that gets dropped, and dropping it turns an empty board into a bug report the reader has to file themselves. An empty board and a board the reader emptied are not the same claim — the second names the control that did it and offers to undo it.

No graph yet
Nothing has been read. Point at a folder and the board draws what is actually there.

No node in this view is a Datastore. The graph still holds ‹total nodes› nodes — the filter is still on.
No traced edge at this level
‹n› nodes survive at ‹level› and the analyzer traced no call between them here. That is a fact about the level, not about the repository.

Three parts in each, in the same order, and the icon is the kind of absence: ic-board nothing read, ic-filter you narrowed it, ic-flow the connections are the thing missing. Not one of the three is coloured; an empty state is not a verdict.

The state this replaces. The board’s scoped-empty is an opaque sheet pinned over the whole canvas carrying one paragraph — no icon, no frame, no radius, and no statement of why. It reads as a crash. An empty state is a .empty box sitting on the board, at the size of what it is talking about, never a lid over it.
08.6

A filter is a focus. A level is a removal.

--board-dim-opacity · one sanctioned deletion

Two controls on this board both look like filtering and are not the same act, and conflating them is what produced the defect below. The kind legend is a focus: matching nodes stay at full strength, the rest recede to --board-dim-opacity, and every edge stays drawn. Nothing is removed, nothing moves, and there is nothing to refit. The depth level is a removal: it genuinely hides nodes, and it pays for that in 08.7.

The mechanism, so it is not rediscovered: an edge is drawn only when both of its endpoints are visible. Any control that removes a whole kind therefore removes every edge incident to it — and a kind filter removes all but one kind, which is every edge on the board. A focus has no endpoints to lose.

08.7

The binding rule: refit the camera

survivors may never hold full‑graph coordinates

Any control that changes the set of nodes on the board is an input to the layout and an input to the camera. If it is not in the layout’s dependencies, the survivors keep positions computed for a graph they are no longer part of, and the camera then fits the bounding box of a graph that is no longer there. The result is a handful of cards stranded at the corners of a field of nothing, at a zoom chosen for the nodes that were removed. Re-run the layout on the surviving set, then fit to it.

08.8

Specify against hundreds, not against five

fixture scale proves logic; a repository proves the result

Every rule on this sheet passes trivially on a fixture of eleven nodes, and passes without being exercised — which is the same as not passing. A graph that fits in the frame never reaches a rung, never fills a module, never reaches a cap, never strands a survivor and never leaves an edge behind. The specimens above are drawn small so they can be read; the specification is written for the field in 08.1.

Handback. This sheet added no class and no token. It does put .kindlegend to a second use — as a census, where each .k carries a count after the name rather than only a name. The shape is identical and the meaning is adjacent (a legend says which kinds exist; a census says how many), so it is recorded here rather than forked into a second class. If a future sheet needs a legend and a census in the same frame, that is the point at which one of them earns its own name.
