## The new mechanism, and the one to keep using

`tools/ci/mutate.mjs` + `tools/ci/mutants.json` break the product on purpose — 34 deliberate
defects — and run the suite that claims to cover each. A suite that stays green while the product is
broken is a hole, reported as a fact.

**It earned its place repeatedly today**, and mostly against my own work: it caught a vacuous test I
wrote, refused to run when a new probe made an existing anchor ambiguous, and reported
INCONCLUSIVE rather than a kill when a suite was red in isolation — which is how a second, hidden
bug surfaced.

`tools/ci/mutants.test.mjs` is the cheap half: ~80ms, proves every mutation still names exactly one
site, so the catalogue cannot rot into decoration. **When a defect is fixed, add the mutant that
re-creates it.**

> chat centre, board right, sessions in a left sidebar, settings bottom-left; no board yet → open on
> the whiteboard; quiet indented work rows.

Needs a **numbered decision**: it overrides `_core.html`'s `.win` chassis (chat LEFT, canvas CENTRE,
rail RIGHT), which every surface is built against. It moves three panes at once, so it must land as
**one change with the e2e geometry suites rewritten in the same commit** — otherwise the shell is
half-moved and nothing holds it.

canvas floor own those pixels. Real half means raising `--pane-w-max` above 640, and the canvas
stops being exactly half, which the substrate draws and two tests are named for.

would make one glyph mean two things). Either they stay words or the glyphs are authored in as a

## The one that did NOT work, and why it is written down

`propose_topology` still never fires on the benchmark:

```
before   TOOLS 0 calls   TOPOLOGY 0 proposals
after    TOOLS 0 calls   TOPOLOGY 0 proposals
```

I widened the trigger and handed the model the real ids. Neither moved it. **I also over-claimed**
by calling it "confirmed twice" — chasing it properly showed the app and the CLI share one
hand-written fence channel, the hint already carries a full worked example, and the app *does* call
the tool in Max's own earlier transcripts.

**So the lever is not a prompt.** It is making "show me this on the board" a deterministic act the
product takes rather than a decision the model may decline — the same argument this repo already
made when it moved proposals off a `seqd` fence and onto a tool call. That is the honest next step.

It also reframes "the MLH board looks a little dry": that answer was an essay, not a rendering
failure.
