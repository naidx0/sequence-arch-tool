# The pointed probe — can the model use the list when told to?

**Registered 2026-09-07, before it runs. A diagnostic, not a measurement, and the difference is
stated below rather than blurred.**

## Why

Two registered measurements have failed to find a use for the carried referent list: mechanism B on
its presence, the placement study on its position. Six placement arms and eighteen turns never
spoke one of the three discriminating names.

What is left is the block's **wording** and the **idea**. This cuts between them for one card-minute:

> **If the model still does not use the three when the question points straight at the list, the
> idea is dead for this model and this task.** If it does, the block's framing is the problem and
> not the information.

## The design, and the trap it avoids

Turn 2 becomes:

> *"Using only the list of dependants you were already given earlier in this conversation, name the
> single one I would have to change first."*

**It points at the list without reproducing it.** A question that named the files would be answered
by copying them back and would prove nothing — the model would be reading the question, not the
block. This one refers to the list and leaves the model to find it.

Everything else is unchanged: same turn 1, same repo, same three-turn shape, `WIRE=1`,
`REFERENTS=1`, `PLACE=tail` (the shipped position, and the one both other studies used).

## What each outcome means, before the data

| turn 2 | reading |
|---|---|
| names one of the three, **no tool ran** | **the block is readable and usable** — only the carry could supply those names, so the failure is the framing. The wording becomes the next registration. |
| names one of the three, **a tool ran** | attribution refused. Inconclusive, and the probe is re-run rather than argued about. |
| names only the five | **the model is answering from prior prose, even when pointed at the list.** Not a pass. The five were spoken by turn 1 and have two sources. |
| names none | **the idea is dead for this model and this task**, and that is the finding worth publishing. |

## What this is NOT

- **Not a measurement.** One or two arms, no control, no kill number in the registered sense. It is a
  diagnostic that separates two hypotheses, and it is labelled that way wherever it is cited.
- **Not evidence about the product's real questions.** Nobody asks *"using only the list you were
  given"*. A positive result would say the information is usable, not that the feature works — those
  are different claims and the second still needs the ordinary question.
- **Not a wording study.** If it comes back positive, the wording study is the next registration and
  has to say in advance what a working wording would mean, because a prompt-shaped fix to a
  prompt-shaped problem is the most over-readable result available here.

## THE PRECONDITION, registered after it was missed

**An arm is VOID unless turn 1 actually called `who_calls`.** Turn 1's tools are the model's choice,
so the list this measures uptake of is not always produced — on the first twelve arms of this stage
it was missing three times, and those turn-2 answers were graded as declining a list that did not
exist.

**The runner decides this, not a reader.** `listProduced` is recorded on every arm and a void arm
exits **6**, meaning re-run me. The file is still written, because a void arm is evidence about the
model's tool choice even if it is not evidence about the carry.

A void arm is replaced, not averaged in, and a batch is capped at three attempts a slot so an arm
that never produces a list is reported as such rather than retried forever.

## Cost and discipline

**Two arms, ~6 minutes of card**, run one at a time. Two rather than one because a single arm cannot
distinguish a result from a coin-flip, and because this stage has already had a first arm disagree
with its replication.

**Nothing else runs on the card while these do** — including diagnostics from this lane. The
placement run lost three arms to exactly that, from inside the lane holding the lock.
