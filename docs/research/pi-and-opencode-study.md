# Pi and OpenCode study: gap map for Sequence's agent

Date 2026-10-12. Read-only research. Pi source read via `gh api` on badlogic/pi-mono (now earendil-works/pi, MIT, pushed 2026-10-12). Pi paths below are relative to https://github.com/badlogic/pi-mono/blob/main/. OpenCode: https://github.com/anomalyco/opencode (MIT; sst/opencode now redirects there).

**Not verified:** Pi's Terminal-Bench 2.0 scores. The author's post says Opus 4.5, five trials, submitted Dec 2025, but the numbers are in images (https://mariozechner.at/posts/2025-11-30-pi-coding-agent/). Do not quote a score until it is read from the leaderboard.

## 1. What Pi is (facts)

- **Prompt plus tool definitions under 1000 tokens** (author's blog). Source shape: one preamble sentence, a one-line-per-tool list, a deduplicated rules list, AGENTS.md as `<project_instructions>`, skills, cwd (`packages/coding-agent/src/core/system-prompt.ts`, `buildSystemPromptSections`, `buildRules`). Rules always end "Be concise" and "Show file paths clearly".
- **Four default tools** `["read","bash","edit","write"]` (system-prompt.ts, `normalizeBuildSystemPromptOptions`). grep/find/ls exist, off by default (blog).
- **read** `{path, offset?, limit?}`; cap 2000 lines or 50KB (`core/tools/truncate.ts:1-12`). Truncation appends `[Showing lines A-B of N. Use offset=K to continue.]` (`tools/read.ts:182-199`).
- **bash** `{command, timeout?}`, no default timeout; output tail-truncated to 2000 lines/50KB, full output saved to a temp file whose path is returned (`tools/bash.ts:41-59,255`; `tools/output-accumulator.ts`).
- **edit** `{path, edits:[{oldText,newText}]}`: each oldText unique in the original file, matched against the original not incrementally, no overlaps. Exact match first, then fuzzy (whitespace/unicode normalisation) (`tools/edit.ts:20-60`; `tools/edit-diff.ts:28-40,207-243`). Tolerates model quirks (edits sent as a JSON string or single object, `prepareEditArguments`). Result details carry `diff`, a unified `patch`, `firstChangedLine` (`edit.ts` `EditToolDetails`). Failure text: `Could not edit file: <path>. <reason>.` (`edit.ts:181`). Writes serialised by `file-mutation-queue.ts`.
- **Sessions:** JSONL entries with `id`/`parentId` (a tree); forks record a parent session path (`core/session-manager.ts:60,182,236`); branch summaries in `core/compaction/branch-summarization.ts`.
- **Compaction:** triggers when `contextTokens > contextWindow - reserveTokens` (defaults reserve 16384, keep-recent 20000) (`core/compaction/compaction.ts:122-129,269`). Estimate is chars/4 plus the last real provider usage (`compaction.ts:194-215,298-344`). Events carry `reason: manual|threshold|overflow`; overflow recovery and auto-retry are explicit events (`core/agent-session.ts:205-235,405`). A context-usage API is exposed (`core/footer-data-provider.ts:97`). The Nov 2025 blog said compaction did not exist yet; the source now has it.
- **Omissions by design:** "skips features like sub-agents and plan mode" (`packages/coding-agent/README.md:19`). Blog: no MCP (Playwright MCP 21 tools / ~13.7k tokens, Chrome DevTools MCP 26 tools / ~18k tokens, 7-9% of a window before work starts); plan = a PLAN.md file; sub-agents = run `pi` through bash. An opt-in MCP bridge exists (`core/mcp-servers.ts`).

## 2. What Sequence does (facts, file:line)

Two paths: ACP (Claude Code, Codex own their loop and prompt) and the built-in loop (local models, API keys).

- **Built-in loop is a large pipeline.** `packages/analyzer/src/server/askPipeline.ts` is 8011 lines; `askTools.ts` is 320KB. `ASK_TOOL_ALLOWLIST` has 22 tools: read_file, edit_file, search_files, read_topology, locate_symbol, who_calls, trace_flow, propose_files, propose_topology, propose_chart, propose_plan, update_todos, write_plan, mark_step_done, walk_example, run_command, git_status, git_diff, call_mcp, call_plugin, fetch_url, report_harness (`askTools.ts:127-180`), plus canvas, board, diagram tools (`:219-224`). Prompt = `basePrompt` + "instruction belt" + carry/goal sections (`askPipeline.ts:4994-5005`). I did not measure its tokens; the pipeline reports a per-turn `contextBreakdown` (`askPipeline.ts:232-238,7865`), so read that from a real turn before quoting a number.
- **Rounds:** `MAX_ASK_TOOL_ROUNDS = 8` (`askTools.ts:523`), ceiling 32 (`:908`).
- **Read cap 12KB** (24KB full permission); comment records 25+ paginated reads on a 2,148-line file, and that 4x (48KB) was slower and solved one fewer instance (`askTools.ts:1055-1067`).
- **run_command output cap 4,000 chars, 30s hard timeout** (longer under full permission) (`askTools.ts:1128-1132`). I saw no tail truncation or saved full output in the lines read; verify in `executeRunCommand`.
- **fetch_url:** one https URL, SSRF/size/time caps, plain text, 6,000-char output cap (`askTools.ts:5310-5350,7182-7192`).
- **edit_file** is sound: refuses with occurrence lines when oldString is ambiguous or missing, or the file does not exist (`askTools.ts:2300-2400`). In review modes it stages a proposal instead of writing (`:1040-1050`).
- **MCP core server** (sent to Claude/Codex sessions): 11 tools (`packages/mcp/src/index.ts:1177`); test-enforced listing budget 2,870 tokens (`packages/mcp/src/test/s2a-session.test.ts:52-59`, chars/4); CORE_INSTRUCTIONS about 1,475 chars, ~370 tokens (`index.ts:1184-1200`). About 3.2k tokens per ACP session versus Pi's whole prompt+tools under 1k.
- **ACP prompt assembly** (`packages/analyzer/src/server/repoServer.ts:8250-8320`): the person's message gets (a) a handoff preamble when the chat moved between agents (`agentHandoff.ts:130-140`), (b) a notes+skills block in FRONT, opening "[Added by the app, not typed by the person; do not mention it. ...]" (`harness/refineNotes.ts:287-322`), (c) when the ask-ledger setting is on, `ASK_LEDGER_INSTRUCTION` appended AFTER, also "do not mention it" (`packages/schema/src/askLedger.ts:25-33`; `repoServer.ts:8314`).
- **Usage meter:** `TurnUsageMeter` estimates nothing (null when unreported) (`packages/acp/src/turnUsage.ts:1-16`); the overview prefers the agent's `usage_update.used`, and admits the fallback for Codex "can read several times the real context" (`packages/web2/src/agents/agentsOverview.ts:93-103`).
- **Stop reasons:** in-loop `complete|ceiling|no-progress|breaker|deadline` (`askPipeline.ts:215,3046-3066`). ACP path passes only refusal vs not (`repoServer.ts` `feed?.end(done.stopReason !== 'refusal' ...)`).
- **Turn status:** `acp:status` ticks every 5s, so a stall is never silent (`agentTurnRuntime.ts:1-23,96`).
- **A/B harness** `tools/bench/agent-ab/`: `run.mjs --agent codex|claude|bash|mock --arm plain|sequence|map`, read-only, 36 questions (`sets/arch-questions-v1.json`), scored by file-set precision/recall/F1 (`score.mjs:30-42`), records wall ms, tokens, tool calls. It measures retrieval for architecture questions only: no edits, no tests, no task completion, and no standard-error code.

## 3. Gap map

| # | Pi | Sequence | Effect on trust / benchmarks |
|---|----|----------|------------------------------|
| 1 | Prompt+tools <1k tokens, 4 tools (blog; system-prompt.ts) | Built-in: 22 tools + canvas/board/diagram, belt (`askTools.ts:127-224`, `askPipeline.ts:4994`); ACP adds ~3.2k MCP (`s2a-session.test.ts:59`) | Small models stall: own note says Codex hit a 32k window with 0 tool calls (`bash-agent.mjs:2-6`). More tool-choice noise, slower prefill. |
| 2 | Only AGENTS.md appended; nothing hidden | App text wrapped around the user's message, told "do not mention it" (`refineNotes.ts:288`, `askLedger.ts:28`) | The agent is told to hide its inputs. When it acts oddly the person cannot see why. Direct trust cost. |
| 3 | Read 2000 lines/50KB, exact "offset=K" continuation (`read.ts:182-199`) | Read 12KB (`askTools.ts:1055`); 25+ reads on one file, 8-round budget (`:1060,523`) | Rounds burned paginating. Our measurement says bigger alone was not better, so test the continuation hint too. |
| 4 | bash: tail 2000 lines/50KB, full output saved to a path (`bash.ts:255`) | run_command 4,000 chars, 30s (`askTools.ts:1128-1132`) | A test verdict lives at the END of output. Truncated or timed-out runs make "tests pass" unverifiable. Top trust gap. |
| 5 | edit returns diff + patch, fuzzy fallback, serialised writes (`edit.ts`, `edit-diff.ts`) | Strict refusal with occurrence lines; no fuzzy fallback seen; review modes stage proposals (`askTools.ts:2300-2400,1040`) | Fewer failed edits on whitespace drift; "done" backed by a visible diff. |
| 6 | Auto-compaction at window-16k with `manual/threshold/overflow` events (`compaction.ts:269`; `agent-session.ts:205-235`) | Handoff/recap for agent switching (`agentHandoff.ts`); built-in long-context handling not traced | No visible threshold event, so "why did it forget" is unanswerable. |
| 7 | Session tree, forks, branch summaries (`session-manager.ts:60,236`) | Rewind and new-thread seed (`repoServer.ts:8250-8300`) | Low priority for benchmarks. |
| 8 | No plan mode, no sub-agents, no MCP by default (README:19; blog) | `propose_plan`, `write_plan`, `update_todos`, `mark_step_done` (`askTools.ts:134-140`) | Extra tools to choose among; test removal. |
| 9 | stopReason aborted/error/length with retry (`agent-session.ts:851,1173`) | Five stop reasons in-loop (`askPipeline.ts:215`), only refusal/not on ACP | Better in-loop; worse on the path used with Claude/Codex. |
| 10 | Terminal-Bench 2.0 submission (blog; scores unverified) | Arch-retrieval F1, n=36 (`score.mjs`) | We cannot claim "better than Codex": no task-completion bench exists. |

## 4. Trust versus a Codex harness

1. **Accurate context meter.** Partly good: `turnUsage.ts` refuses to guess; the overview prefers the agent's own `used`. Gap: the Codex fallback can overstate by several times (`agentsOverview.ts:93`); no threshold warning found. Show `used/size` only when `usage_update` supplies both, else "unknown".
2. **Diffs before "done".** Pi returns diff and patch from every edit. For ACP agents the "done" claim is the agent's prose; I found no server-side check that claimed files changed (`git_diff` exists, but only as a tool the agent may skip).
3. **Running tests.** `run_command` at 4,000 chars / 30s (`askTools.ts:1128`) cannot hold a normal test run. Likely contributor to "I don't trust it": it can claim a pass without seeing the verdict. This is a hypothesis from code reading, not yet reproduced on Max's chats; reproduce there before accepting it.
4. **Honest stop reasons.** In-loop yes (`askPipeline.ts:215`); ACP path no.
5. **No injected noise.** Fails: two app-authored blocks around the person's message that instruct "do not mention it" (`refineNotes.ts:288`, `askLedger.ts:28`) and an unmeasured belt on the in-loop path. Codex sends the user's text plus AGENTS.md. Fix: show injected blocks as a collapsed labelled row; drop "do not mention it".

## 5. Ranked changes (at most 6)

Win bar everywhere: paired mean difference > 2 SE, SE = sd(per-question differences)/sqrt(n). The harness has no SE code; add it to `score.mjs` first (test-locked).

0. **Prerequisite, a task arm.** Add `--task` sets to `run.mjs`: pinned repo commit, one edit request, hidden test command; metric = pass rate. Without it, changes 2, 4, 5 cannot be judged. Files: `tools/bench/agent-ab/run.mjs`, `score.mjs`, new `sets/edit-tasks-v1.json`.
1. **Run output like Pi.** Tail-truncate to 2000 lines/50KB, save full output to a temp file and return its path, add an explicit `timeout` arg with a longer default. Files: `askTools.ts:1128-1132`, `executeRunCommand`. A/B: edit tasks with a failing test; metrics pass rate and "claimed pass but failed" rate; n >= 30; win bar > 2 SE on paired pass rate.
2. **Stop hiding injected text.** Move the notes block and ledger line into a visible collapsed row; remove "do not mention it". Files: `harness/refineNotes.ts:287-322`, `schema/src/askLedger.ts:25-33`, `repoServer.ts:8250-8320`. A/B: injected vs plain on the arch set, F1, n=36 x 3 repeats; goal is non-inferiority (loss < 0.02 F1 at > 2 SE). The trust gain itself is a user check, not a benchmark.
3. **Read continuation hint, retune window.** Add `[Showing lines A-B of N. Use offset=K to continue.]`; compare 12KB/24KB/50KB. Files: `askTools.ts:1055-1067`, `executeReadFile`. A/B: bash agent, arch set; metrics tool calls per answer and F1; n=36; win bar > 2 SE on calls saved with F1 not lower.
4. **Trim the tool belt.** Core set (read, edit, search, run_command, git_diff) vs full allowlist on a local model. Files: `askTools.ts:150-180`, `askToolsForJobMode` (:357). A/B: arch set + edit tasks; F1, pass rate, tokens in; n=36; win bar > 2 SE.
5. **Fuzzy edit fallback and diff in the result.** Port normalise-and-retry; return the patch from edit_file. Files: `askTools.ts:2240-2400`. A/B: edit tasks; edit refusal rate and pass rate; n >= 30; win bar > 2 SE.
6. **ACP stop reasons and honest context meter.** Surface `stopReason` beyond refusal; show "unknown" instead of fallback. Files: `repoServer.ts` near `feed?.end`, `web2/src/agents/agentsOverview.ts:93-115`. Check by replaying recorded turns (`packages/acp/src/replay/`): displayed vs reported `used`, all fixtures, bar 0 mismatches.

## 6. Browser and web access (OpenCode)

- **webfetch** (MIT): input `{url, format: "text"|"markdown"|"html" (default markdown), timeout? (<=120s, default 30)}`; output `{url, contentType, format, output}`. Plain HTTP GET with a browser-like User-Agent and per-format Accept header; http/https only; textual MIME only; bounded body; retries once with another UA on a Cloudflare challenge; HTML to markdown with `htmlparser2` in an in-repo converter (not turndown); permission asked per URL; no key. https://github.com/anomalyco/opencode/blob/dev/packages/core/src/tool/plugin/webfetch.ts and `.../tool/html-markdown.ts`.
- **websearch:** input `{query}`; providers exa, firecrawl, parallel, tavily, tinyfish (`packages/core/src/plugin/websearch/`). Exa calls the hosted MCP endpoint `https://mcp.exa.ai/mcp`, tool `web_search_exa`, `numResults: 8`, adding `exaApiKey` only if configured (`.../websearch/exa.ts`), so it works keyless. I did not test rate limits or Exa's terms for third-party apps; check before copying that endpoint.
- **Browser plugin** (`packages/plugin-browser`, MIT): tabs.open/list/focus/close, navigate, snapshot, find, evaluate, click, fill, screenshot, console, network, lighthouse, trace; every call needs a `tabID` and a permission. The desktop shell owns the browser, so it is not usable without OpenCode's desktop app (that package's README).
- **Sequence today:** `fetch_url` (`askTools.ts:5310-5350`) and `BrowserPane`, a URL field plus fetch result that its header says is "not embedded Chromium pretending to be a full browser" (`packages/web2/src/browser/BrowserPane.tsx:1-30`). No webview, `web_fetch` or search tool found in `packages/web2` or `packages/analyzer`.
- **Recommendation:** upgrade `fetch_url` to the webfetch design (format param, HTML to markdown, 30s default/120s max, byte bound, Cloudflare UA retry, Pi-style "continue at offset" tail) instead of the 6,000-char plain text. Keep the SSRF guard and `wrapUntrustedLines`. Add a keyless `web_search` only after the owner picks a provider (hosted Exa MCP is a third-party dependency; self-run SearXNG is the alternative). Defer a real browser tool: Pi's cost argument (13.7k tokens for 21 tools) applies, and the BrowserPane header rejects embedded Chromium.
