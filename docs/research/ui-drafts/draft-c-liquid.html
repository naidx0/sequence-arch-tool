A next-token predictor in a loop

Everything else — tools, memory, planning, this harness — is scaffolding around one operation repeated a few thousand times a second.

  1. Tokenise. Your text becomes ~4-character pieces the model holds embeddings for.
  2. Attend. Every token weighs every earlier token and decides what matters.
  3. Predict. The stack emits a probability over the whole vocabulary; sampling picks one.
  4. Repeat. The chosen token is appended and the loop runs again from the top.

Where this gets interesting for sequence is step four, because that same loop is where a tool call comes from — the model emits

▶ Thought for 6s 4 steps

User wants a mental model, not an API tour. Lead with the loop; everything else hangs off it.

Four steps is the right granularity — three hides attention, five drags sampling temperature in and that is a different question.

They are in this repo, so land step four on tool calls; that is the bridge from "what is an LLM" to "what is this harness doing".

Do not mention parameter counts. Nobody has ever been helped by that number.
