# 0.1.8 backend plan

End state: every BE row in `docs/requests/2026-10-12-checklist.md` is built, tested and merged on
`backend/0.1.8`, and the claims-audit plan (`_cloud-handoff/claims-audit/PLAN.md`) phases are carried
forward on the same branch. The UX chat integrates; nothing is released from here.

Base: `origin/main` @ 6c7da59f (release 0.1.7 + one marketing commit). Out of scope: anything visual
(UX chat), sites, a public release, signing keys.

## Wave 1 (three builders, disjoint files)

### A. Components engine (sonnet, `wip/018-components`)
Owns: `packages/analyzer/src/components/**` (new), `packages/analyzer/src/test/components-*.test.ts`,
`packages/mcp/src/componentTools.ts` (new) + its registration lines in `packages/mcp/src/index.ts`,
the run-node prompt seam and `/api/components*` routes in `packages/analyzer/src/server/repoServer.ts`,
`packages/web2/src/components/**` (new client + model), the `/components` entry in
`packages/web2/src/chat/composerModel.ts`.
Win line:
1. A component is never in the prompt by default (test: a Claude/Codex thread prompt with mode `cards`
   and no match contains no component text; listing tokens of the new MCP tool ≤ 150).
2. `matchComponents("can you reverse engineer this binary")` returns `security/reverse-engineer-anything`;
   "explain how this app works" returns nothing from REA (its description says skip for source repos).
3. Mode `auto`: a matching turn gets the component body once per thread (ledger) and a
   `components:loaded` event. Mode `cards`: no body, a `components:offer` event the chat can show as an
   approval card; accepting re-sends with `components: [id]`. Mode `off`: no offer, no tool, only explicit
   load via `/components` or the + menu.
4. `/components [list|auto|cards|off|<id>]` in the slash registry; `GET/PUT /api/components`,
   `POST /api/components/load`. Mode persists in the server store, not localStorage.
5. Components with `status: review` (REA) are never auto-loaded, even in `auto`; they always ask.

### B. Component catalog (haiku, `wip/018-catalog`)
Owns: `packages/analyzer/components/**` (new data dir), `tools/components/**` (vendor script).
Win line: `node tools/components/vendor.mjs --check` exits 0; every bundled component has `SKILL.md`,
`component.json` and the upstream license text; the catalog has no component from a repo without a
license; pinned commit per source.

### C. Context meter (sonnet, `wip/018-context`)
Owns: `packages/acp/src/turnUsage.ts`, `packages/web2/src/agents/agentsOverview.ts`,
`packages/web2/src/agents/agentActivity.ts`, new `packages/web2/src/agents/contextMeter.ts`, the
context read in `packages/web2/src/shell2/StatusBar.tsx` (one call site only), their tests.
Win line (all fail today):
1. A chat whose runs sum to 15M processed tokens shows context ≤ the reported window size; context is
   never a sum across requests or turns.
2. For the same chat the status bar and the Agents pane show the same context number (one function).
3. Switching chats never carries another chat's context into the status bar.
4. Two near-identical prompts in one thread inject byte-identical prefix blocks (no word-dependent
   block on the second turn); measured on the run-node prompt builder.
5. Cumulative totals are labelled "processed", never "context".
