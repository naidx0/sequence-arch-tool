Part 4: Next build slices (6 Oct 2026)

Inputs: the parity checklist (Part 5), the harness study of T3 Code, OpenCode and Synara (Part 6), and the uiarc.dev and Bastion UI pass (Part 7). "SYNARA" is Synara (github.com/Emanuele-web04/synara, MIT). It is an open-source desktop GUI for Claude Code, Codex, OpenCode and others, started from a T3 Code clone.

Main finding. Most of the distance to Claude Code or Codex is data the two CLIs already send that Sequence throws away. The ACP client sends clientCapabilities: {} and mcpServers: [], sends prompts as text only, never resumes a session, and reads only message text. Closing that is mostly wiring, not invention.

How every slice is checked (applies to all)

  • Replay first. Record a few Codex sessions once, covering edits, a command approval, a plan, a todo list, a long silent tool and usage updates, with 5 runs at most on the ChatGPT plan. Then replay them through the real adapter, reducer and UI state, as T3 Code does in replay.ts. Claude is signed out on this machine, so build its fixtures from the ACP schema and the claude-agent-acp tests (Apache-2.0), and label Claude as "not run live".
  • Tests wait for queues to drain and never sleep. Fake clocks handle anything with timeouts.
  • Each merge runs changed-package tests only. Screenshots are taken once per batch, and are always taken before a big visual change. The full gate runs late.
  • Perf claims use the ratchet file's deterministic counts.

The mirror's acp/src/client.ts throws almost all of this away. It sends clientCapabilities: {} and mcpServers: [], sends the prompt as text only ([{type:'text'}]), never calls session/load, and reads nothing from updates except agent_message_chunk. Top 12 gaps, ranked by value and effort

  1. Agent context survives restarts (row 10). Add loadSession / resume to AcpAgentClient in acp/src/client.ts and persist agentSessionId on SessionIndexEntry in analyzer/src/server/sessionsStore.ts. On a cache miss, analyzer/src/server/acpSessionCache.ts then resumes instead of calling newSession; the Codex bridge does the same with thread/resume. Without this, every idle period over 10 minutes or any app restart silently drops the agent's memory, which runs against the owner's "sessions end late" goal.

  2. Image paste and board snapshots to the agent (row 7). Remove the image refusal in web2/src/chat/attachmentModel.ts, store blobs through analyzer/src/server/attachmentStore.ts, and let prompt() in acp/src/client.ts take content blocks (image, resource_link). The Codex bridge sends localImage. As a bonus, the existing PNG board export can go to the agent as context.

  4. Code checkpoints for CLI edits (row 3). 2. T3 Code (MIT)

  • Surfaces. apps/web (React 19 with React Compiler), apps/desktop (Electron, which bundles the server), apps/mobile (Expo/React Native) and apps/server (Node, WebSocket).
  • Shared logic lives in packages/client-runtime (connection, state, work-log presentation) and packages/contracts (typed RPC).
  • Web and mobile share @legendapp/list and @pierre/diffs. Mobile adds native markdown, diff and terminal modules (apps/mobile/modules/*).
  • Server. Event-sourced. orchestration-v2/EventSink.ts commits events, projections, the command receipt and outbox effects in one transaction, and EffectWorker.ts runs side effects afterwards.
  • Resume. A bounded snapshot plus snapshotSequence, then afterSequence replay capped at 128 events or 1 MiB, with a snapshot fallback (ThreadStream.ts).
  • A single supervisor retries with jittered backoff capped at 5 minutes (client-runtime/src/connection/supervisor.ts).
  • Transport health is tracked separately from data freshness (docs/internals/connection-runtime.md).
  • The sidebar "shell" stream is separate from per-thread streams. Thread streams are reference-counted with a 5-minute cache, and desktop keeps running threads alive (apps/web/src/state/threads.ts).
  • Wire budget. Tool output and file bodies are dropped from the stream and strings are truncated at 32 KB (WireProjection.ts). A cold open sends 75 rows or about 1 MiB, and older history pages over HTTP. vp run test:perf:v2-wire enforces these budgets (docs/internals/performance-regressions.md).
  • Streaming. ThreadLiveEventCoalescer.ts keeps the latest in-flight update per tool-call id within 50 ms. LiveStreamBudget.ts caps each subscriber at 1,000 items or 8 MB. apps/web/src/markdown-incremental.ts caches the parsed prefix that ends at a closed code fence.
  • UI performance.
  • components/chat/MessagesTimeline.tsx: LegendList with maintainScrollAtEnd and recycleItems.
  • DiffWorkerPoolProvider.tsx: diffs highlighted in a worker pool with an LRU cache.
  • lib/visibleAnimation.ts: animations pause off screen and in hidden tabs.
  • Route autoCodeSplitting and lib/chunkReloadGuard.ts for bundles.
  • How agent work is shown.
  • ComposerPendingApprovalPanel.tsx: docked approvals with a "1/N" counter and a "provider gone" state.
  • ComposerTasksBadge.tsx: todo segments.
  • ProposedPlanCard.tsx: plan cards.
  • ProviderSubagentBar.tsx: subagents.
  • QueuedRunsControl.tsx: queue or steer messages during a run.
  • client-runtime/src/work-log/commandLabel.ts: unwraps zsh -lc into a readable program name.
  • Checkpoints are hidden refs under refs/t3/checkpoints (apps/server/src/checkpointing/). Turn end and settling are separate milestones (RunFinalizationService.ts).
  • Testing. Provider-neutral replay transcripts replace only the provider process (packages/effect-codex-app-server/src/replay.ts, docs/orchestration-v2/testing-strategy.md). Tests drain workers instead of sleeping (packages/shared/src/DrainableWorker.ts). AGENTS.md says "Do not run repo-wide checks."

3. OpenCode (MIT)

  • Client/server. An Effect HTTP API with an SSE event stream (packages/opencode/src/server/routes/instance/httpapi/handlers/event.ts): listeners register eagerly, server.connected comes first, and a heartbeat follows every 10 s.
  • The TUI, the SolidJS app (packages/app) and the Electron desktop (packages/desktop) are all clients of a generated SDK (packages/sdk).
  • app/src/context/server-sdk.tsx merges part updates and concatenates deltas, then flushes once per frame inside batch().
  • Sessions.
  • session/overflow.ts: auto-compaction at the usable context minus 20k tokens.
  • session/compaction.ts: prunes old tool output.
  • tool/truncate.ts: output capped at 2,000 lines / 50 KB, with the full output spilled to a file.
  • Undo and redo. snapshot/index.ts keeps a shadow --git-dir outside the repo and runs write-tree with no commits. In session/revert.ts, revert sets a pointer and restores files, unrevert restores the earlier state, and messages are deleted only on the next prompt.
  • Share links. share/share-next.ts syncs events to /api/share/<id>/sync. The share page reuses the packages/session-ui renderer.
  • Agents. agent/agent.ts defines build and plan (plan denies edits) plus the subagents general and explore. The task tool can resume a subagent by task_id. agent/subagent-permissions.ts passes the parent's denies down to subagents.
  • Permissions. permission/index.ts: the last matching rule wins and the default is ask.
  • A reject with a message becomes feedback to the model, and a reject cancels the session's other pending requests.
  • "Always" automatically resolves other matching requests.
  • permission/arity.ts makes "always" grant git checkout, not all of git.
  • LSP. After an edit, tool/edit.ts appends <diagnostics>, with at most 20 errors per file (lsp/diagnostic.ts).

3. Rules

  1. CSS-only. Port Arc's numbers, not its code; add no Motion.
  2. Loops animate only transform and opacity. Loops that must repaint use steps(): for example, board-run-edge .9s steps(9) cuts about 60 paints a second to about 10. Replace chatpot with R1b.
  3. Every loop stops. Pause it when the window is hidden (R13). Use content-visibility:auto on messages. Ambient loops are finite. At most one shimmer and one spinner per surface.
  4. Loader tiers. Show nothing under 250 ms. Then:
  5. inline wait: ring or braille;
  6. live label: shimmer;
  7. lists: finite skeleton;
  8. known amount: determinate bar; unknown amount: hairline;
  9. boot: braille plus one status line.
  10. Durations. Hover 120 ms; exit and tooltip 160; enter, popover and toast 240; showpieces 480. Add --dur-3/--dur-4 and the Arc easings next to --dur-1/2.
  11. Glass only on small floating surfaces: composer, ⌘K, menus, board toolbar, toasts. At most three on screen. Never on panes, rows or overlays, and never glass on glass. Dark recipe: fill rgba(255,255,255,.08–.13), rim .14–.20, inset 0 1px 0 rgba(255,255,255,.18), blur(16–20px) saturate(1.6–1.8).
  12. Blur only over moving or detailed content. Panes over a static ground keep the alpha fill and drop the blur; it looks the same and is free.
  13. Accessibility. Reduced transparency makes glass solid; reduced motion shows a static glyph.
  14. Icons. One 24-unit set, round caps. Stroke 1.5 at ≤14 px, 1.6–1.75 at 16–24 px. Sizes 14 / 16 / 20, and 24 in empty states.
  15. Type. Weights 400/500, sentence case, tabular numbers.
  16. ASCII only on first run, boot and empty states. ≤12 fps, one mono font. It stops on the first action and is static under reduced motion. Never on the board.
  17. Shell widths snap. A width spring makes xyflow re-measure every frame.
  18. Streaming. One fading span per flush and a steps(1) caret. No per-word spans, no blur.
  19. Overlays. Enter 150–240 ms, close 120–160 ms. Tooltips 250 / 300 ms. Dialogs dim, never blur.
  20. Approvals. Hold-to-confirm 1.2 s; confirm-morph reverts after 6 s. Enter approves, Esc rejects.
